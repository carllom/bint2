PROTOTYPE — THROWAWAY — issue #7

Recycled DOM rows vs canvas for the v1 hex renderer

Plan §11 defaults to recycled DOM rows for v1 (canvas kept as a documented fallback). This demo pushes a ~60–120 row recycled pool — repositioned with transform: translateY, text rewritten on scroll — over a synthetic multi-GB byte source, so you can feel the two things that decide the call: (1) does it hold frame rate under sustained wheel / auto scroll, and (2) does native text selection across recycled rows survive well enough for phase 1, or does linked hex↔ascii selection + copy force a canvas + custom selection model regardless? Drive it in every target browser (Chrome, Firefox; WebKit best-effort). The pure module the real code keeps is HexRowRenderer at the bottom of this file — the frozen seam.
